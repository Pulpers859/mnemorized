# Two-Chapter Workflow Trial: 72-73

## Bottom Line

**Upfront exact-prior retrieval helped, but net usage or cost savings are NOT
established.** It eliminated one visible failure pattern in this sample: neither
first cue draft held a term while overlooking an already-selected exact same-term
record. It did not eliminate semantic, overrigid-hold or association-accounting
errors. Independent stronger review remained necessary.

Do not interpret this trial as proof that cheaper agents produce equivalent
creative work. No lower-model authorship arm was run. One stronger AI author
handled both chapters; main was the independent non-author reviewer/integrator.
There were no human-specialist, learner or image evaluations.

## What Changed

The author first froze a source term/keyword inventory, without cue decisions.
Main checked actual source regions and ran the existing exact-casefold prior
tool BEFORE authoring. Both chapters used prior universe 1-71, plus explicit
local comparisons when drafts shared a new association. Historical holds were
not automatically vetoes; selected roots were evidence, not compulsory copying.

Main supplied a compact exact-prior packet. No smaller agent was hired just to
run a deterministic script. One local common assembler generated both banks,
source enums, exact prior copies and counts from explicit author decisions;
the author did not write another bespoke materializer. Authoring, independent
review and first/repair freezes remained separate.

These are multiple workflow changes, not a controlled test of retrieval timing
alone. The assembler is a source-specific local trial tool, not a new generic
production pipeline. Its setup, testing and one relative-path bug repair count
as effort; hiding them would overstate efficiency.

association/comparison accounting rather than the selected picture.

Material findings included:

- An undefined `adrenaline-style` alarm did not actually encode adrenal. That
  proposal was withdrawn, not rescued with a vague stylistic description.
- Ordinary stationary placement did not encode stasis; that scope claim was
  removed from the cholestatic-jaundice proposal.
- Sacroiliitis used an ileum model as a phonetic helper, creating an avoidable
  wrong-anatomy collision. The model was removed; only a sack opening-sound
  reminder remains, explicitly omitting anatomy and the rest of the name.
- Meclizine and B12 holds inconsistently demanded stronger naming than accepted
  partial/category cues. Both were reconsidered with explicit limits, not
  claimed empirically successful. Only these local first-draft holds resolved.
- Pear/peri and biliary-model/stone duplicates were not counted twice as fresh
  yield. Den, rotation and other genuinely different lexical/action bridges
  were separated from mere reuse of a germ or other visual ingredient.

Main read all 401 materialized cue/scope rows, source keyword mappings and real
source regions, checked actual prior copies and targeted comparisons, then
reviewed only changed decisions for closure. No full-corpus semantic-novelty
claim and no repeated whole-source review after bounded repairs.

## Honest Efficiency Evaluation

Observed evidence:

- Source inventory phase took 918 seconds (about 15.3 minutes) of elapsed agent
  time, including preparation corrections. This is not active effort or billing.
- Final exact lookup took about 0.54 seconds combined. It is cheap deterministic
  work; an additional agent merely dispatching it would add a handoff.
- First cue freezes occurred about 14.2 minutes and 22.1 minutes after the first
  observed phase 2 timestamp. Both were saved before an account usage pause.
- Same author resumed after the multi-hour pause; no new cohort, inventory
  recreation or source rescan. Pause time is excluded from efficiency inference.
- Both first cue drafts had ZERO held-with-selected-exact-prior flags. A
  retrospective lookup of unchanged 69/70 first freezes found 9 such flags among
  283 terms. Those were leads, not 9 proven errors; opioids ultimately remained
  intentionally held. Source topics, difficulty and contracts differ.
- Pre-creative source work still needed coordinate corrections and meaningful
  head additions. Early repair is still work, not a zero-defect inventory.
- Two semantic review/repair rounds and substantial author/integrator record
  writing remained. Exact per-agent tokens, quota weights and dollars are not
  exposed here. No claim of measured net savings or equivalent difficulty.

**Recommended next workflow:** retain upfront deterministic retrieval and
independent stronger cue judgment. Reuse the tooling rather than rebuilding it
per batch. The next efficiency improvement is a genuinely sparse author contract:
code copies source text/font/coordinates from selected span IDs and inherits
unchanged prior cue metadata; the model writes only semantic choices, changed
scope and exceptions. The current inventory still transcribes too much metadata,
and even its compact decision file repeats substantial prose. This trial does
not prove that overhead is already solved, or authorize silently rewriting the
frozen trial to make its result look cheaper.

Use a smaller helper only when a nontrivial bounded extraction/exception task
justifies its preparation and review. Do not downgrade creative selection or
remove independent review to manufacture apparent savings. A future sparse
contract needs its own bounded quality/effort comparison, not assumed benefit.
